# PubMed confirmatory queue. Cora is the diagnostic; this is the check that a conclusion drawn on
# 2708 nodes survives 19717.
#
#   ONLY_GPU=4 ./scripts/run_queue.sh scripts/queue_pubmed.txt &
#   ONLY_GPU=5 ./scripts/run_queue.sh scripts/queue_pubmed.txt &   ... etc
#
# Why 3 epochs and not 20:
#   PubMed's train split is 11830 examples against Cora's 1624. Holding *epochs* fixed would give
#   PubMed 7.3x Cora's optimisation budget and cost 90 h per arm, and any difference between the
#   two datasets would then confound dataset with budget. Holding the *example budget* fixed
#   instead: Cora 20 x 1624 = 32480 examples, PubMed 3 x 11830 = 35490, within 9%. So 3 epochs.
#   Evaluation every epoch, since there are only three.
#
# Why random_rewire is absent:
#   It is the density control for ego_star and the most droppable arm in the plan. Cora carries
#   the density argument; repeating it here buys little for 13.5 h.
#
# Caution recorded before the first result arrives: a smoke run with no completed optimiser step
# already scored 91.67 (n=24) on PubMed NC, against TAG-DLM's reported 96.30, on a 3-class
# problem. If that survives a real run of the `none` arm, PubMed NC is close to saturated by text
# alone and cannot discriminate between structure encodings -- which would itself be a result, and
# is why `none` is first in this queue rather than last.
